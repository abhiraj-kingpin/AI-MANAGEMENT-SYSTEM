# Model Cards

Minimal model-governance documentation for every real ML component this backend loads at runtime — loosely following the structure Mitchell et al.'s ["Model Cards for Model Reporting"](https://arxiv.org/abs/1810.03993) (FAT* 2019) established as standard practice, scaled to what a project this size actually needs: what each model is, where it came from, what's been measured about it, and what hasn't.

This file is the human-readable counterpart to [`manifest.json`](manifest.json) in this same directory, which [`tests/shared/modelManifest.test.ts`](../tests/shared/modelManifest.test.ts) verifies against the real files on disk on every test run — checksums and sizes here are asserted facts, not just claims. This document itself isn't machine-checked (prose can't be), so treat any specific number here as accurate as of the version noted, not necessarily the current one — the per-model CHANGELOG entries cross-referenced below are the append-only source of truth if this file and the code ever disagree.

## MobileFaceNet (`w600k_mbf.onnx`)

|                  |                                                                                                                                                                                                                                                                   |
| ---------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **Purpose**      | Face embedding — maps an aligned 112×112 face crop to a 512-dim vector for cosine-similarity identity matching                                                                                                                                                    |
| **Architecture** | MobileFaceNet                                                                                                                                                                                                                                                     |
| **Source**       | [InsightFace `buffalo_s` model pack](https://github.com/deepinsight/insightface/releases/download/v0.7/buffalo_s.zip), official release                                                                                                                           |
| **License**      | MIT                                                                                                                                                                                                                                                               |
| **SHA-256**      | `9cc6e4a75f0e2bf0b1aed94578f144d15175f357bdc05e815e5c4a02b319eb4f`                                                                                                                                                                                                |
| **Size**         | 13,616,099 bytes (13.6 MB)                                                                                                                                                                                                                                        |
| **Input**        | `[1, 3, 112, 112]` float32, RGB, `(pixel - 127.5) / 128` normalization, planar (NCHW)                                                                                                                                                                             |
| **Output**       | 512-dim float32 vector (output name `516`), L2-normalized by this repo's own code before storage/comparison                                                                                                                                                       |
| **Added**        | `backend-v1.1.6`                                                                                                                                                                                                                                                  |
| **Used by**      | `src/modules/face-recognition/faceEmbedding.provider.ts` (server-side registration/verification), `mobile-app/assets/models/w600k_mbf.onnx` (identical checksum, on-device inference via ONNX Runtime's Flutter binding, `backend-v1.1.6`-equivalent mobile work) |

**Intended use**: matching a live face against an employee's previously-registered face(s) for attendance check-in, and detecting duplicate registrations across employees (`analytics.ai.service.ts`'s `duplicate_face` anomaly). Not intended, and not evaluated, for any use beyond 1:1 or small-gallery 1:N verification within this application.

**Evaluation**: real-measured, not assumed. `scripts/lfw-eval.ts` (`backend-v1.1.9`) ran this exact model through this repo's own detect→align→embed→cosine-match pipeline against LFW (Labeled Faces in the Wild)'s standard `pairsDevTest.txt` split — 989/1000 pairs processed (11 skipped for no detectable face in at least one image). Same-person pairs: mean cosine similarity 0.588. Different-person pairs: mean 0.003. Best empirical threshold 0.24 → 96.97% verification accuracy, 0% measured false-accept rate. Production `FACE_MATCH_THRESHOLD` (`config/env.ts`) set to `0.3` — inside the zero-FAR range with deliberate margin above the razor's-edge empirical peak. Full threshold sweep table in the `v1.1.9` entry of [`../CHANGELOG.md`](../CHANGELOG.md).

**Known limitations**: LFW is mostly well-lit, front-facing, professional photographs of public figures — a real but imperfect proxy for this deployment's own employees under this deployment's own phone/webcam conditions, which have never been separately measured (no dataset of real people beyond LFW exists in this environment). Mobile's copy of this model is fed landmarks from a _different_ detector (Google ML Kit, not SCRFD) through the same alignment math — its own end-to-end accuracy has not been separately measured either; see [`mobile-app/README.md#face-check-in`](../../mobile-app/README.md#face-check-in).

## SCRFD Face Detector (`det_500m.onnx`)

|                  |                                                                                                                                                   |
| ---------------- | ------------------------------------------------------------------------------------------------------------------------------------------------- |
| **Purpose**      | Face detection — finds every face-like region in a photo, with a confidence score, bounding box, and 5 landmarks (eyes, nose, mouth corners)      |
| **Architecture** | SCRFD                                                                                                                                             |
| **Source**       | Same [InsightFace `buffalo_s` pack](https://github.com/deepinsight/insightface/releases/download/v0.7/buffalo_s.zip) as the embedding model above |
| **License**      | MIT                                                                                                                                               |
| **SHA-256**      | `5e4447f50245bbd7966bd6c0fa52938c61474a04ec7def48753668a9d8b4ea3a`                                                                                |
| **Size**         | 2,524,817 bytes (2.5 MB)                                                                                                                          |
| **Input**        | `640×640` float32, RGB, `(pixel - 127.5) / 128`, aspect-preserving resize + black padding                                                         |
| **Output**       | 9 tensors — 3 strides (8/16/32) × {score, bbox-distance, keypoint-distance}, 2 anchors per spatial location                                       |
| **Added**        | `backend-v1.1.7`                                                                                                                                  |
| **Used by**      | `src/modules/face-recognition/faceDetector.ts`                                                                                                    |

**Intended use**: locating and aligning the face in a registration/check-in photo before embedding — a preprocessing step for the model above, not a standalone product feature.

**Evaluation**: no quantitative accuracy metric — this environment has no labeled face-detection dataset (LFW's ground truth is identity labels, not bounding boxes, and isn't suited to measuring detection recall/precision). What _is_ verified: anchor generation, bbox/keypoint decoding, and NMS thresholds were checked line-by-line against InsightFace's own published `scrfd.py`, not derived from memory; real output shapes were confirmed by actually running inference against this exact file; and, once, manually, against a real CC0-licensed portrait photo (downloaded temporarily, never committed to this repo) — one correct detection, a visually-accurate bounding box, anatomically plausible landmarks. Automated tests (`tests/modules/face-recognition/faceRecognitionModels.test.ts`) cover what's verifiable without a real face on file: a featureless image produces zero detections, determinism, output-shape correctness, non-crash on unusual aspect ratios.

**Known limitations**: detection recall/precision on real, varied faces (different angles, lighting, occlusion, skin tones) has never been quantitatively measured in this environment — the manual check above is one photo, one data point, not a benchmark.

## MiniFASNet-V2 Anti-Spoofing (`minifasnet_v2.onnx`)

|                                |                                                                                                                                                                                                                                                                                                                                                                                                                                  |
| ------------------------------ | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **Purpose**                    | Single-image presentation-attack detection (PAD) — classifies a face crop as live, a printed photo, or a screen/video replay                                                                                                                                                                                                                                                                                                     |
| **Architecture**               | MiniFASNetV2 (`embedding_size=128, conv6_kernel=(5,5), drop_p=0.2, num_classes=3, img_channel=3`)                                                                                                                                                                                                                                                                                                                                |
| **Source**                     | [`garciafido/minifasnet-v2-anti-spoofing-onnx`](https://huggingface.co/garciafido/minifasnet-v2-anti-spoofing-onnx) on Hugging Face — an ONNX export (torch 2.2.2 → opset 11) of [`minivision-ai/Silent-Face-Anti-Spoofing`](https://github.com/minivision-ai/Silent-Face-Anti-Spoofing)'s published `2.7_80x80_MiniFASNetV2.pth` weights, bit-equivalent per that repo's own model card (format conversion only, no retraining) |
| **Upstream weights checksum**  | `2.7_80x80_MiniFASNetV2.pth` SHA-256 `a5eb02e1843f19b5386b953cc4c9f011c3f985d0ee2bb9819eea9a142099bec0` (not committed to this repo — the ONNX conversion is what's used)                                                                                                                                                                                                                                                        |
| **License**                    | Apache-2.0 (same as upstream; attribution: Beijing Mininglamp Vision Technology Co., Ltd.)                                                                                                                                                                                                                                                                                                                                       |
| **SHA-256 (this repo's copy)** | `d7b3cd9ba8a7ceb13baa8c4720902e27ca3112eff52f926c08804af6b6eecc7b`                                                                                                                                                                                                                                                                                                                                                               |
| **Size**                       | 1,744,116 bytes (1.7 MB)                                                                                                                                                                                                                                                                                                                                                                                                         |
| **Input**                      | `[1, 3, 80, 80]` float32, **BGR** (not RGB), `pixel / 255` → `[0, 1]`, cropped with a 2.7×-margin box centered on the detected face's bounding box before resizing                                                                                                                                                                                                                                                               |
| **Output**                     | `[1, 3]` raw logits — `[live, print-attack, replay-attack]`; this repo applies softmax and computes `liveScore = 1 - (p[print] + p[replay])`                                                                                                                                                                                                                                                                                     |
| **Added**                      | `backend-v1.1.9`                                                                                                                                                                                                                                                                                                                                                                                                                 |
| **Used by**                    | `src/modules/face-recognition/livenessDetector.ts`, wired into `face.service.ts#register()`'s per-photo loop                                                                                                                                                                                                                                                                                                                     |

**Intended use**: rejecting a registration photo of a printed photo or a screen replay of someone else's face. Deliberately scoped to registration only — `face.service.ts#verify()` (check-in matching) only ever receives a pre-computed embedding vector from the client, never a raw image, so this model cannot and does not run at check-in time. The mobile app's separate blink-based liveness check (`BlinkLivenessChecker`, temporal, client-side, at check-in) is a complementary, not overlapping, signal — see [`mobile-app/README.md#face-check-in`](../../mobile-app/README.md#face-check-in).

**Evaluation**: none in this environment — no labeled real-vs-spoof (print/replay attack) dataset exists here to measure against (LFW, used for the embedding model above, is entirely genuine photos). `LIVE_THRESHOLD` (`livenessDetector.ts`, `0.5`) is the algorithmically natural "which class wins" cut for a 3-class softmax collapsed to live-vs-not, not an empirically-tuned number — the same class of open, documented gap `FACE_MATCH_THRESHOLD` had before `scripts/lfw-eval.ts` existed.

**Known limitations**: no measured false-accept/false-reject rate for actual print or replay attacks. The 2.7×-margin crop-and-resize preprocessing is a direct, line-for-line port of the upstream project's own `CropImage._get_new_box`/`crop`, but the final resize step is this repo's own from-scratch bilinear implementation (reusing `faceAlign.ts`'s already-tested sampler) rather than a verified-byte-identical match to the upstream's `cv2.resize` — this environment has no OpenCV/Python to cross-check against.

## Isolation Forest (`shared/ml/isolationForest.ts`) — algorithm, not a downloaded model

|                    |                                                                                                                                                                                                                                                                                                                                                                                                                                  |
| ------------------ | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **Purpose**        | Unsupervised anomaly detection over per-employee attendance-pattern features (mean/spread of check-in time, late rate, average overtime)                                                                                                                                                                                                                                                                                         |
| **Algorithm**      | Isolation Forest ([Liu, Ting & Zhou, ICDM 2008](https://ieeexplore.ieee.org/document/4781136)) — the same algorithm behind scikit-learn's `IsolationForest`                                                                                                                                                                                                                                                                      |
| **Implementation** | From scratch in this repo (`shared/ml/isolationForest.ts`) — not an npm dependency, so there's no external package/version/license to track the way there is for the ONNX models above. Verified instead by known-outlier synthetic tests (`tests/shared/isolationForest.test.ts`): a planted outlier in a synthetic cluster scores 0.7+ while every inlier stays well below it, and scoring is deterministic given a fixed seed |
| **Training**       | Fit fresh to real data on every call, not persisted — `analytics.ai.service.ts#detectAttendancePatternAnomalies` builds a new forest from the organization's own current attendance data on each `/analytics/ai/anomalies` request. Default parameters: 100 trees, sample size `min(256, employeeCount)`, seed `42`                                                                                                              |
| **Added**          | `backend-v1.1.10`                                                                                                                                                                                                                                                                                                                                                                                                                |
| **Used by**        | `src/modules/analytics/analytics.ai.service.ts`                                                                                                                                                                                                                                                                                                                                                                                  |

**Intended use**: flagging an employee whose attendance pattern is jointly unusual across several dimensions at once (a case the sweep's other, per-dimension rule-based checks structurally can't catch) — one signal among four in the `/analytics/ai/anomalies` sweep, not a standalone fraud determination.

**Evaluation**: no labeled "this attendance pattern was actually fraudulent" dataset exists in this environment (the same limitation the two ONNX-model thresholds above have). `ATTENDANCE_PATTERN_ANOMALY_SCORE` (`analytics.ai.service.ts`, `0.65`) is a real but deliberately conservative choice comfortably above the algorithm's own neutral-baseline score of `0.5`, not a measured optimum.

**Known limitations**: requires at least 5 employees with attendance data in the window to run at all (`MIN_EMPLOYEES_FOR_PATTERN_ANALYSIS`) — below that, "anomalous relative to the group" isn't a meaningful statement. No real-world precision/recall measurement exists for this specific deployment's own data.

## What "minimal" means here

This is deliberately not a model registry, a versioned artifact store, or an automated retraining pipeline — none of those have real infrastructure behind them in this environment (no object storage, no scheduled jobs beyond what's already documented as a gap elsewhere in this repo). What this _does_ provide, for real: a single place documenting provenance and license for every model in production use, a machine-checked integrity guarantee that the files on disk are still what they claim to be, and an honest, per-model account of what's actually been measured versus what remains an open, acknowledged gap — the same standard of honesty this repo's [`README.md`](../README.md#known-simplifications--future-work) and [`CHANGELOG.md`](../CHANGELOG.md) already hold every other part of the codebase to.
